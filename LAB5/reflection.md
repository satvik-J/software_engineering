# Reflection on Static Code Analysis

## 1. Purpose of Static Code Analysis

Static code analysis helps identify potential bugs, security vulnerabilities, code quality issues, and style violations without executing the program. In this lab, I used Pylint, Bandit, and Flake8 to analyze the flight reservation system and improve its quality, security, and maintainability.

## 2. Experience with Pylint, Bandit, and Flake8

Pylint helped identify code quality issues, including unused variables, naming conventions, and unnecessary global statements. Bandit helped identify potential security concerns, such as the use of `eval()` and the use of a standard pseudo-random generator for security-sensitive values. Flake8 identified formatting issues, including lines exceeding the recommended length and unused imports.

Using these three tools helped me understand that each tool focuses on a different aspect of code quality and that they work well together.

## 3. Issues Identified and Fixed

During the analysis, I identified issues such as unused imports, overly long lines, broad exception handling, unused local variables, comparisons with `None` using an inappropriate pattern, and missing a newline at the end of the file. I also reviewed security-related findings reported by Bandit.

I made changes to improve the code's readability, follow Python coding conventions, and reduce potential security risks. I then reran the analysis tools to verify the changes.

## 4. Challenges Faced

One challenge was understanding the messages generated by the different tools and locating the corresponding lines in the Python file. I also encountered a file path issue when running the analysis commands from the wrong directory. I resolved it by navigating to the directory containing `flight_reservation_system.py` before running the commands.

Another challenge was distinguishing between style warnings and issues that could affect the program's security or behaviour. Reviewing the findings individually helped me decide which changes were necessary.

## 5. Importance of Static Analysis

Static analysis is useful because it can detect problems early, before the software is deployed. It encourages consistent coding practices, makes programs easier to maintain, and helps developers identify potentially unsafe operations. However, static analysis does not replace testing because a program can pass these checks and still contain logical errors.

## 6. Conclusion

This lab helped me understand how static analysis tools improve Python code quality and security. By using Pylint, Bandit, and Flake8, I learned how to interpret warnings, make corrections, and verify the results through subsequent analysis. The final Pylint score achieved for my project was 9.67/10, which exceeds the lab's required score of 9.5/10. This experience demonstrated the importance of combining automated analysis with careful code review and testing.
